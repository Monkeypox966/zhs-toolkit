# 使用说明

## 安装与登录

在项目目录运行 `uv run zhs` 即可；依赖同步、登录恢复、课程发现和未完成任务续跑自动进行。
默认先复用 Cookie，失效后尝试 SSO 续期；仍需登录时自动显示二维码，无需增加 `--qrlogin`。
Windows 和 macOS 默认弹出二维码窗口，无法打开时回退到终端显示，其他系统默认在终端显示。
二维码过期或手机取消本次扫码后自动刷新，手机确认登录后继续原任务。
终端显示方式可用 `--show-in-terminal` 或 `--no-show-in-terminal` 指定。
已有 Cookie 保存在 `var/cookies.json`，无需每次重新扫码。
配置为账号密码优先时，凭据缺失或被平台拒绝会自动转为扫码，不再要求退出后手动更换命令。
临时网络错误不会清空 Cookie 或触发无意义的密码登录。扫码账号与原任务不一致时会提示重新扫描，
校验成功后才覆盖本地 Cookie。等待扫码时可使用 Ctrl+C 或停止命令退出。

配置文件为 `config/config.json`。初次运行会自动生成，也可以从同目录的示例文件复制后修改。
账号密码登录取决于平台验证要求；显式 `--no-qrlogin` 强制仅使用账号密码，此时拒登会保存原因并退出。

## 参数

| 参数 | 用途 |
| --- | --- |
| `stop` | 保存状态并停止同一数据目录中的运行实例，无需登录 |
| `--check` | 只检查登录与课程列表 |
| `--dry-run` | 解析课程并保存任务计划，不执行学习或测试 |
| `--resume [RUN_ID]` | 继续指定或最近一次运行中的未完成任务 |
| `--retry-failed [RUN_ID]` | 只重试失败和待处理任务 |
| `--report PATH` | 导出本次运行记录为 JSON；路径相对当前工作目录 |
| `--history` | 查看最近运行记录，不登录 |
| `--once` | 只执行一轮，不自动恢复；省略时默认持续处理未完成内容 |
| `-f`, `--fetch` | 保存全部类型课程到 `var/execution.json` |
| `-c`, `--course ID [ID ...]` | 指定课程 |
| `-v`, `--videos ID [ID ...]` | 指定视频，需同时指定课程 |
| `-ai`, `--aicourse COURSE_ID CLASS_ID` | 指定 AI 课程 |
| `--noexam` / `--exam` | 跳过 / 启用 AI 测试 |
| `-l`, `--limit MINUTES` | 单门课程时限，0 表示不限 |
| `-s`, `--speed NUMBER` | 播放速度，必须为有限正数 |
| `-t`, `--threshold NUMBER` | 完成阈值，必须为有限正数 |
| `--tree-view` / `--no-tree-view` | 开启 / 关闭课程树 |
| `--progressbar-view` / `--no-progressbar-view` | 开启 / 关闭进度条 |
| `--image-path PATH` | 保存登录二维码 |
| `--proxy URL` | 设置代理 |
| `-d`, `--debug` | 开启调试日志 |
| `-h`, `--help` | 查看完整参数 |

布尔参数接受 `true/false`、`yes/no`、`1/0`。保留 `--tree_view`、`--progressbar_view`、
`--show_in_terminal`、`--image_path` 和 `--noexam False` 等原有写法。

## 停止与重新运行

```powershell
uv run zhs stop  # 可在另一个终端停止前台或后台运行
uv run zhs       # 自动停止旧实例，随后在当前终端恢复未完成任务
```

`stop` 不读取账号配置，不登录，也不启动学习任务；没有运行实例时正常返回。
停止请求在等待、视频进度更新、扫码轮询和 AI 流处理中检查；正在发送的网络请求先等待返回或超时。
已经开始提交的试卷会完成本次提交及评分、缓存和检查点处理后再退出；异常结果仍保留待核实记录。
旧实例保存状态、关闭客户端并释放执行锁后，新实例才开始运行。已完成任务及有效缓存会继续复用。
默认等待最多 120 秒；超时会报错并保留停止请求，不强杀旧实例，也不启动第二个执行实例。
再次执行启动或停止命令可以继续等待。使用不同 `ZHS_HOME` 的实例互不影响。
`--history`、`--help` 和 `--version` 不影响正在执行的实例；`--check`、`--fetch` 和 `--dry-run`
不会主动停止学习实例，执行锁被占用时会提示稍后重试。`stop` 不能与其他执行参数组合。
升级前启动且没有控制信息的旧实例需要先手动停止一次；新版不会根据进程名批量结束 Python。

## 配置字段

| 字段 | 用途 |
| --- | --- |
| `username`, `password`, `qrlogin` | 登录方式与账号配置 |
| `save_cookies` | 是否保存并复用登录态 |
| `proxies` | Requests 代理配置 |
| `tree_view`, `progressbar_view`, `qr_extra`, `image_path` | 终端及二维码显示 |
| `logLevel` | 日志等级 |
| `pushplus`, `bark` | 可选通知服务 |
| `ai.enabled`, `ai.use_zhidao_ai` | 是否启用 AI、是否使用平台内置 AI |
| `ai.openai` | 外部 AI 地址、密钥与模型 |
| `ai.max_exam_attempts` | 每个知识点最多尝试次数，默认 5 |
| `ai.ppt_processing` | PPT 转文本服务与清理策略 |

跳过测试时不校验未使用的 AI 服务配置。外部 AI 的 `api_base` 支持带或不带 `/v1`。
PPT 服务使用 `moonShot.base_url`；`delete_after_convert` 控制转换后删除本项目上传的文件。
缓存清理只使用本地上传清单，不扫描账号的其他远程文件。

## 课程清单

```json
[
  {"name": "共享课", "id": "COURSE_SECRET", "type": "zhidao"},
  {"name": "校内课", "id": "COURSE_ID", "type": "hike"},
  {"name": "AI 课", "id": "COURSE_ID", "classId": "CLASS_ID", "type": "ai"}
]
```

旧清单中仅有 `id` 的普通课程仍然可用。指定 `--once` 时，默认从本地清单选择课程，空清单表示不执行课程。
默认自动模式直接发现全部课程，避免旧清单漏课；`-c`、`-ai` 和 `-v` 仍用于限制处理范围。
任一课程来源获取失败时，`--fetch` 不覆盖原清单。

## 续跑与运行记录

每次普通执行都会在 `var/runs/` 建立一份 JSON 记录，保存任务、执行选项、账号摘要、
每次尝试的状态、错误类型、起止时间和耗时。`latest.json` 指向最近建立的计划。
报告不保存账号密码、Cookie 或 AI 密钥；错误文本沿用现有日志行为。

```powershell
uv run zhs --dry-run --noexam
uv run zhs                            # 自动恢复最近一次未完成任务
uv run zhs --retry-failed RUN_ID --report var/retry-report.json
uv run zhs --history
```

续跑会跳过已成功的课程或视频，并复用此前的时限、速度、阈值和是否跳过测试的设置；
显式提供的参数优先。课程内部根据平台进度和答案缓存恢复，不保证从某一行代码或某个请求原位继续。
日常无需指定 `--resume`；该参数只用于手动选择历史记录。达到时限的任务会在续跑时重新尝试；
`--retry-failed` 只选失败和待处理项。

进程异常退出时，记录中的 `running` 任务会在加载时恢复为 `interrupted`。更换账号后拒绝直接续跑。
收到 `KeyboardInterrupt` 时记录中断类型、时间及调用位置，不把无法确定来源的中断归因为用户操作。
中断和停止提示会单独换行，提示下次直接运行 `uv run zhs`，避免与尚未结束的进度条拼在一起。
如果最初课程发现不完整，自动模式会重新获取清单，向原计划补入遗漏课程，并保留原有进度。

默认自动模式会在一轮结束后继续恢复失败和待处理项，重试间隔从 30 秒逐步增加到最多 300 秒，
有完成进展后恢复短间隔。没有总轮数上限，Ctrl+C 可停止；每个知识点一轮内仍受测试次数上限约束。
成功项不会重复执行，每轮会刷新缓存的课程上下文，已确认全对的知识点测试从记录恢复并跳过。
同一个知识点测试出错后继续处理其他知识点；一门课程失败后先处理其他课程，再回头恢复。
默认不指定课程时，会复用最近未结束的计划并扩展为全部课程；未完成的视频计划也会自动恢复，
随后继续发现同课程的其他内容。重复相同课程选择也会复用匹配的未完成计划。
自动模式在执行后重新读取平台进度，学习进度尚未完成时继续处理，默认完成阈值为 1.0。
显式提供的 `--noexam`、课程范围和时限仍然生效；如需保留单轮行为，添加 `--once`。

答题优先使用有效缓存，其次调用 AI。AI 请求或答案解析、校验失败时恢复旧版随机作答兜底：
单选和判断选择 1 项，多选选择 2 项（不超过选项总数），然后继续保存答案、提交试卷。
随机答案不会直接写入正确答案缓存；提交后只缓存平台返回且通过校验的正确选项，后续尝试优先使用缓存。
每个知识点仍受 `ai.max_exam_attempts` 限制，默认最多 5 次；平台未返回正确选项时不保证重试能答对。
题型不支持、题目结构无效、达到时限或用户中断时不会随机绕过这些错误。
提示文本使用保守的 27,900 UTF-8 字节预算，超长时裁剪前部参考资料，保留末尾题目与选项。
长度控制完全在本地完成，不依赖在线下载分词表；初始化 AI 客户端不会因分词资源网络错误阻塞知识点。

发送提交请求前先将 `submitting` 检查点落盘，
响应确认后记为 `accepted`，全部题目都有可识别评分后记为 `reviewed`。
提交请求超时、响应无法解析、提交后读分失败或进程突然退出时，未完成的检查点会阻止直接重新提交，
并标记 `SubmissionUncertainError`。自动模式会只读查询原试卷和评分，不重新开卷或提交；
取得全部评分后更新答案缓存、恢复记录，再继续课程。评分仍不可用时保持待处理并在冷却后复查。
自动模式会暂时跳过待确认测试所属知识点的测试，继续处理同课其他资源和知识点；旧记录缺少知识点标识时保留整项保护。
提交接口明确返回 HTTP 401/403 时记录为 `rejected`，重新登录后可重试，不进入评分等待。
超时、连接中断或服务器错误仍视为结果不确定；读取评分时返回 401 也不会把已接受的提交改成“拒绝”。
`--once` 不进行这类自动恢复。检查点机制不保证跨平台请求的严格一次执行。

自动恢复不代表能绕过平台验证或完成未实现协议的任务。账号错误、验证码、短信或实名验证，
以及平台一直不返回的评分，仍可能阻止最终完成；这类状态不会被伪装为成功。

运行记录还会保留进程意外退出的尝试历史，未知的结束时间和耗时不会编造。续跑的汇总包含此前已完成的结果；
执行器没有返回任何确认结果时按失败处理。

`--report PATH` 会在任务开始前写出计划，结束或异常后更新报告；路径不可写时不执行课程任务。
报告可以覆盖已有的运行报告，拒绝覆盖其他现有文件，也不能导出到 `var/runs/` 内。

## 缓存与多实例

`cache.max_files`、`cache.max_size_mb`、`cache.max_age_days` 控制本地资料下载和转换文本的总文件数、
总大小和保留时间。默认分别为 500、1024 MiB、30 天。文件数或容量为 0 时不保留对应本地缓存，
天数为 0 时关闭按年龄清理。只清理本项目格式的缓存文件，保留无关文件和远程上传清单。

同一 `ZHS_HOME` 下只允许一个 CLI 执行实例，其他实例会直接报告资源占用；`--history` 可在运行时查看记录。
锁由操作系统管理，进程退出即释放；`.lock` 文件保留是正常行为，不代表锁仍被占用。
直接使用 Python 接口时，同一运行记录也有独立进程锁；实例保存或执行时会检查版本，
如果记录已由其他实例更新，需要重新调用 `RunJournal.load()`。

资料下载拒绝空内容，未压缩响应会核对 `Content-Length`，失败时不留下可用缓存或临时下载文件。
默认每次下载使用 300 秒的耗时预算，在收到数据块后检查；连接和读取仍受请求自身超时约束。
直接使用 `PptToTxt` 时可通过 `download_timeout_seconds` 调整预算。

## 日志与退出状态

日志位于 `var/logs/`，每个文件达到 5 MiB 后轮转，保留 3 份备份。
调试模式沿用项目现有行为，会记录请求参数和 Cookie。

结束时汇总完成、失败、待处理和跳过数量。失败或待处理返回 `1`，用户中断返回 `130`，正常结束或仅达到时限返回 `0`。
正在进行的网络请求仍受自身超时约束，因此课程时限不保证在精确到秒的时间点立即结束。
